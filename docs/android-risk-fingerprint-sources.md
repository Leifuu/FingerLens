# Android 风控指纹公开来源（第一批）

更新时间：2026-10-26。本文只记录公开可核验的资料和可映射到普通 Android App 的信号，不把任何单一信号当作“欺诈结论”。

## 官方 Android 网络资料

- [ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager)：定义活动网络查询入口。
- [NetworkCapabilities](https://developer.android.com/reference/android/net/NetworkCapabilities)：公开 transport 与 capability，例如 VPN、VALIDATED、CAPTIVE_PORTAL、NOT_METERED、NOT_ROAMING、TRUSTED 等；本工程的 `network/risk-signals.capabilityStates` 还记录 INTERNET、NOT_SUSPENDED、NOT_CONGESTED、临时非计费、非带宽受限、企业网络和本地网络能力，旧的顶层能力字段继续保留，低版本以 `null` 表示不适用。
- [ProxyInfo](https://developer.android.com/reference/android/net/ProxyInfo)：公开默认代理主机、端口、排除列表和 PAC URI；本工程新增 `network/proxy-summary`，只记录是否配置、主机存在性/长度/ SHA-256、端口、排除项数量和 PAC scheme，完整 `network/proxy` 原始条目继续保留。
- [LinkProperties](https://developer.android.com/reference/android/net/LinkProperties)：公开活动链路 Private DNS 是否启用、活动链路 DNS 服务器列表和服务器名称；本工程新增 `network/private-dns-summary`，只记录链路状态、DNS 地址族计数和名称 SHA-256，不复制 DNS 地址或名称原文。
- 本工程新增 `network/risk-signals`，只保存活动链路的这些公开能力、是否计费、接口名和代理摘要；值仍由 `ItemSink` 独立记录状态，VPN 或代理不会被自动判定为恶意。
- 本工程新增 `network/connectivity-summary`，汇总可见网络数量、活动链路、transport、VALIDATED、VPN 和链路属性可用性，不复制地址、DNS、路由或原始字符串。

## Wi-Fi 芯片标准支持

2026-10-26 核对 [WifiManager.isWifiStandardSupported(int)](https://developer.android.com/reference/android/net/wifi/WifiManager#isWifiStandardSupported(int))、[ScanResult 标准常量](https://developer.android.com/reference/android/net/wifi/ScanResult) 与SDK37公开版本表：方法自API30公开；LEGACY=1、11N=4、11AC=5、11AX=6自API30，11AD=7自API31，11BE=8自API33。LEGACY表示802.11a/b/g集合，不分别查询a/b/g，也不查询UNKNOWN=0。

在线取得[固定AOSP Android15源码](https://android.googlesource.com/platform/packages/modules/Wifi/+/refs/tags/android-15.0.0_r1/framework/java/android/net/wifi/WifiManager.java#4282)，文件SHA256为 `c0f0a71c9f8e43a6474ebac55a2a6b957c301731d75b0f2976a82275a419d50b`，明确该方法查询芯片对指定标准的支持并委托给Wi-Fi系统服务。常量数值同时由本机SDK35公开ScanResult源码核对，API边界由SDK37的api-versions.xml核对。源码契约不是当前设备实现的证明，运行时逐项验证单独进行。

新增独立 `network/wifi-standard-support`，保留 `managerAvailable`、`scope: "chipset-supported-wifi-standards"`、实际尝试数 `queryCount`、固定上限 `queryLimit:6` 及六项原序 `entries`。每项 `standard/status/supported` 独立：API不足为unsupported/null；可查询版本但无服务为unavailable/null；成功false为有效返回；SecurityException为denied、UnsupportedOperationException或NoSuchMethodError为unsupported，其余Exception/LinkageError为error，异常类单独保留，单项失败不抹去其它项。API30最多4次、31/32最多5次、33+最多6次；旧版本或无服务不调用getter。

复用现有ACCESS_WIFI_STATE声明，只读能力，不发起扫描、不切换Wi-Fi/网络、不读取SSID/BSSID或新标识。此项是平台对芯片能力的响应，独立于原 `network/wifi-capabilities.wifiStandard` 当前链路标准，不代表频段、链路速率、接入点支持、实际协商/传输成功或永久设备身份。原Wi-Fi链路、缓存和摘要项保留；旧JSON缺项不补写，完整字段按JSON类型展示，保留未知字段和50行分页，异构/空对象/null也保留原值，窄屏横向查看双侧。

当前Pixel6/API36独立instrumentation快照中，六项与同UID直接getter一致：1/4/5/6为true，7/8为false。3新增与2旧Wi-Fi测试通过；24/29/30/31/32/33/37版本分支、无服务与异常来自明确合成测试，不宣称这些版本均有真机验证。定位与附近Wi-Fi运行时权限未授予的本次测试仍可读取六项；未修改权限或网络状态，未生成正式Release全量报告。

## Android 安全环境资料

- 音频公开属性（2026-10-26）：[AudioManager.getProperty](https://developer.android.com/reference/android/media/AudioManager#getProperty(java.lang.String)) 按固定键返回字符串或无值null。已核对SDK37常量与API版本表：`PROPERTY_OUTPUT_SAMPLE_RATE`、`PROPERTY_OUTPUT_FRAMES_PER_BUFFER`自API17公开；`PROPERTY_SUPPORT_MIC_NEAR_ULTRASOUND`、`PROPERTY_SUPPORT_SPEAKER_NEAR_ULTRASOUND`自API23公开；`PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED`自API24公开，均满足本项目minSdk24。[固定AOSP AudioManager.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/AudioManager.java#L6840-L6915) 说明前两项是低延迟输出流的原生或最佳采样率（十进制Hz）及缓冲区PCM帧数；近超声声明针对默认麦克风音源/默认扬声器路径的18–21kHz，未处理音源声明针对预期频率范围及电平响应。该固定实现前两项无正值时返回null，后三项来自平台布尔资源；不假定厂商设备运行相同源码，也不把配置声明当作声学测量或活动音频流状态。
- 新增五个独立采集项 `hardware/audio-property/output-sample-rate`、`output-frames-per-buffer`、`mic-near-ultrasound`、`speaker-near-ultrasound`、`source-unprocessed`。通过普通App UID调用getter，每项保留准确来源、原始字符串（含空串/空白/前导零）或null；最大2048字符，超长失败明确记录而不静默截断，单项SecurityException/异常不会丢掉其它属性或旧音频项。null表示getter没有值，不伪造数值0/false；不将文本true/false转为JSON布尔，不用ADB shell补值，不录音、播放、打开音频流、调整路由或新增权限。旧JSON缺项沿用单侧比较。
- 当前Pixel6/API36独立instrumentation将完整硬件采集sink中的五项逐一与公开getter核对：字符串`"48000"`Hz、`"128"`PCM帧、麦克风近超声`"true"`、扬声器近超声`"true"`、未处理音源`"false"`。三项Android测试通过，空串/null/2048与2049字符/拒绝及方法错误为合成边界测试。另导出明确标注的仅五项API验证报告，通过浏览器双侧逐值与来源检查；它不是正式全量采集报告，不证明实际超声频响、实时延迟或录放音成功。

- 扬声器布局展示补充（2026-10-26）：音频设备概览新增独立查询状态及原始通道掩码，每页5设备。仅数字0/1分别附[CHANNEL_INVALID](https://developer.android.com/reference/android/media/AudioFormat#CHANNEL_INVALID)/[CHANNEL_OUT_DEFAULT](https://developer.android.com/reference/android/media/AudioFormat#CHANNEL_OUT_DEFAULT)名称（本机公开SDK37 android.jar常量值已核对）；字符串、负值、未知整数、成功null与失败保留原样，不从掩码推断扬声器数量或物理坐标。旧侧缺对象显示未采集，双侧均无对象时不增加摘要；已采集对象的未知字段继续参与完整原对象比较并提示核对完整字段。布局完整字段保留JSON类型，数字1与字符串"1"、布尔与同文字符串不会被格式化合并；复杂已知结构回退原字段表，旧音频字段及profile/混音分页保持。此增量仅改变浏览层；验证使用既有独立API证据与旧报告组成的HYBRID样本、明确标注的SYNTHETIC样本和旧真实报告，不冒充新正式采集。

- 内置扬声器声道布局（2026-10-26）：[AudioDeviceInfo.getSpeakerLayoutChannelMask](https://developer.android.com/reference/android/media/AudioDeviceInfo#getSpeakerLayoutChannelMask()) 自API36公开；已核对SDK37的API版本表和[固定AOSP AudioDeviceInfo.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/AudioDeviceInfo.java#L586-L600)。其契约限定仅对TYPE_BUILTIN_SPEAKER有效，掩码说明平台返回的扬声器通道，物理布局还应参照多声道标准；不能由此推断扬声器数量、坐标、朝向、当前输出格式或播放成功。该固定实现为FlaggedApi，本工程仍只调用公开getter，SDK满足时如方法不可用则独立保留异常。
- `hardware/audio[*].speakerLayout` 保存`status/channelMask`，API36以下unsupported/null、API36+非TYPE_BUILTIN_SPEAKER为not-applicable/null且不调用getter；适用时原始32位有符号整数（含0及未知位）不变，异常denied/error/null并附errorClass。查询独立于旧设备/audioProfiles/混音字段，不回填其它声道掩码，不录放音、不调整音频路由、不新增权限；旧JSON无对象仍可导入和比较，完整字段保持分页。Pixel6/API36的内置扬声器（id3/type2）公开getter与采集sink均返回1，其余8设备不适用；SDK37常量及上述AOSP注解包含CHANNEL_INVALID=0、CHANNEL_OUT_DEFAULT=1，不能把原始1解释成单声道。API24/35门槛、原始0/负数/极值与异常为合成测试，尚无低API或厂商异常真机证据。

- 混音属性展示补充（2026-10-26）：`hardware/audio` 的设备概览增加混音查询状态、总数/返回数/上限/截断及空/null/旧未采集说明；明细按原始序号每页5项对照行为、编码、采样率和声道位置/索引掩码、声道数，保留重复。仅数值行为0/1附默认/位精确名称，字符串、未知整数、负掩码原样展示，能力列表不代表当前配置或实际播放成功。设备与明细行都比较完整原始对象，未知元数据/属性字段、完整哈希及类型变化继续标差异；已知文字相同但未知字段变化时提示核对完整字段。保留原设备/profile概览和完整字段折叠/50行分页，混音完整字段保留JSON类型，防止数字或布尔与同文字符串被差异筛选漏掉；只对混音对象启用，旧音频字段格式不变。旧JSON不补写，空列表不推导硬件不支持；混音异构结构或超过64项明细回退完整字段，390px窄屏可独立横向查看设备B。此轮只优化浏览层，不改变采集、导出或通用比较规则。

- 音频设备支持的混音属性（2026-10-26）：[AudioManager.getSupportedMixerAttributes](https://developer.android.com/reference/android/media/AudioManager#getSupportedMixerAttributes(android.media.AudioDeviceInfo)) 与 [AudioMixerAttributes](https://developer.android.com/reference/android/media/AudioMixerAttributes) 自API34公开；已核对SDK37版本表和固定AOSP的 [AudioManager.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/AudioManager.java#L9875-L9894)、[AudioMixerAttributes.java](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/AudioMixerAttributes.java)。返回可用作偏好配置的格式与混音行为，DEFAULT=0、BIT_PERFECT=1；公开说明仅USB设备保证暴露可配置混音属性，其它设备可以返回空列表。该固定上游实现底层查询失败时也返回空列表，故无法据空列表区分未声明、不可配置与底层失败，也不假定设备正运行此提交。
- `hardware/audio[*].supportedMixerAttributes` 新增独立查询状态、总数/返回数/上限/截断、完整集合SHA256及前64项明细。每项保留混音行为、采样率Hz、编码、声道位置/索引掩码和声道数六个原始整数；最多接受256项输入，原序/重复进入完整原序JSON的UTF8哈希，不推导组合。公共getter正常返回空列表记为ok/[]，API34以下unsupported/null、服务缺失unavailable/null、异常denied/error/null并保留异常类；查询失败不丢失原设备字段或audioProfiles。只调用getter，不设置混音偏好、不打开音频流、不播放或录制、不新增权限；能力列表不代表当前配置或bit-perfect播放成功。旧JSON缺对象不补写，既有完整字段折叠及50字段分页直接展示新数据，原设备概览按完整对象比较并保留未知字段差异。低API分支、非空及超限为合成测试；当前Pixel6/API36的9个设备均返回空列表，尚未实测USB设备的非空结果。

- `virtualization/risk-summary` 汇总 RootBeer/Talsec 类公开检查的路径存在性、构建字符串标记和 `test-keys` 线索；逐路径 JNI 结果仍保留，摘要只标记 `evidenceOnly`，不形成自动风控结论。

## 资源语言集合（公开 SDK 实现对照）

- [FingerprintJS Android 的 DevicePersonalizationInfoProvider](https://github.com/fingerprintjs/fingerprintjs-android/blob/a9c2bf327877115481049935dd99e8e78dae0cf0/fingerprint/src/main/java/com/fingerprintjs/android/fingerprint/info_providers/DevicePersonalizationInfoProvider.kt)（2026-10-26 经 GitHub API 获取固定提交源码）：`availableLocales()` 读取注入的 `AssetManager.locales`。这是开源 Android 指纹库的可核验实现，不据此推导其 Pro 服务端或其它供应商的私有字段。
- [AssetManager.getLocales](https://developer.android.com/reference/android/content/res/AssetManager#getLocales())、[Resources.getSystem](https://developer.android.com/reference/android/content/res/Resources#getSystem()) 与 [AOSP AssetManager](https://github.com/aosp-mirror/platform_frameworks_base/blob/main/core/java/android/content/res/AssetManager.java)：公开 API 自 API 1 可用；AOSP 说明 API 21+ 返回 BCP-47 标签，旧版本曾使用 `ll_CC`，`getLocales()` 包含系统资源，`getNonSystemLocales()` 是隐藏 API，本工程不调用后者。
- 新增 `environment/resource-locales`，分别读取当前 App 已加载资源和系统 Resources 的 AssetManager 语言集合；它们不是用户当前语言，也不证明 APK 自身提供全部这些翻译。每组保存原始数量、null 数量、最多 256 项排序明细、截断状态和完整 JSON 数组的 UTF-8 SHA-256；保留重复项、空字符串、null、旧语言代码和未知标签，不做标签归一化。缺失数组不伪装为空集合。集合受系统资源、覆盖层、APK/依赖和已加载资源影响，不是永久硬件标识；旧语言条目与 schema 1.0 不变。
