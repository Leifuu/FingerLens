# Android 风控指纹公开来源（第一批）

更新时间：2026-10-26。本文只记录公开可核验的资料和可映射到普通 Android App 的信号，不把任何单一信号当作“欺诈结论”。

## 官方 Android 网络资料

- [ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager)：定义活动网络查询入口。
- [NetworkCapabilities](https://developer.android.com/reference/android/net/NetworkCapabilities)：公开 transport 与 capability，例如 VPN、VALIDATED、CAPTIVE_PORTAL、NOT_METERED、NOT_ROAMING、TRUSTED 等；本工程的 `network/risk-signals.capabilityStates` 还记录 INTERNET、NOT_SUSPENDED、NOT_CONGESTED、临时非计费、非带宽受限、企业网络和本地网络能力，旧的顶层能力字段继续保留，低版本以 `null` 表示不适用。
- [ProxyInfo](https://developer.android.com/reference/android/net/ProxyInfo)：公开默认代理主机、端口、排除列表和 PAC URI；本工程新增 `network/proxy-summary`，只记录是否配置、主机存在性/长度/ SHA-256、端口、排除项数量和 PAC scheme，完整 `network/proxy` 原始条目继续保留。
- [LinkProperties](https://developer.android.com/reference/android/net/LinkProperties)：公开活动链路 Private DNS 是否启用、活动链路 DNS 服务器列表和服务器名称；本工程新增 `network/private-dns-summary`，只记录链路状态、DNS 地址族计数和名称 SHA-256，不复制 DNS 地址或名称原文。
- 本工程新增 `network/risk-signals`，只保存活动链路的这些公开能力、是否计费、接口名和代理摘要；值仍由 `ItemSink` 独立记录状态，VPN 或代理不会被自动判定为恶意。
- 本工程新增 `network/connectivity-summary`，汇总可见网络数量、活动链路、transport、VALIDATED、VPN 和链路属性可用性，不复制地址、DNS、路由或原始字符串。

## Android 安全环境资料

- 基础振动单元展示补充（2026-10-26）：`hardware/vibrator` 在原始 `vibrators` 字段组中增加对照概览，每页5个振动器，按原始数组序号保留重复振动器和重复基础单元。各侧逐项显示公开名称及原始编号、支持标志与平台估算时长（毫秒），不把0改成未知或从时长推导支持；未知编号、字符串编号、null、false、空列表、未采集与查询失败分别保留。完整振动器对象（含未知字段、类型变化）决定整行差异，对象键书写顺序不作为差异；原始逐字段表默认折叠且保留50字段分页。旧JSON无基础单元对象时沿用原表，一侧新一侧旧时明确显示未采集，不补写原值；结构不完整、超过概览上限（32个振动器或每侧64个单元）时回退完整字段，不截断原始数据。390px窄屏可独立横向查看两侧。此轮只调整浏览层，不修改采集、比较规则、JSON输入或导出。

- 显示模式展示补充（2026-10-26）：`display/*` 的 `supportedModes` 采用每页20项概览，按原始序号逐行显示模式ID、原始分辨率/刷新率及HDR查询状态、类型名称与原始编号（Dolby Vision=1、HDR10=2、HLG=3、HDR10+=4，来自下述固定AOSP源码）。保留重复模式；HDR概览最多列前8项并明确省略，完整字段默认折叠且保留50字段分页。完整哈希和未知字段变化仍标记整行差异，旧JSON缺少每模式HDR时显示未采集，不从整体HDR列表补值；缺项、null、空字符串、失败及未知值保持区别，结构不完整时回退原表。本次只优化浏览，不修改采集、比较规则、JSON原值或导出。

- 显示模式 HDR 类型补充（2026-10-26）：[Display.Mode.getSupportedHdrTypes](https://developer.android.com/reference/android/view/Display.Mode#getSupportedHdrTypes()) 自 API 34 返回某个显示模式支持的 HDR 类型；已核对本机 SDK 37 API 版本表和[固定 AOSP 实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/core/java/android/view/Display.java#L2516-L2523)。`display/*` 的 `supportedModes[*].hdrTypeSupport` 保存查询状态、原始整数类型及数量，保留 API 返回顺序、重复与未知值；最多接受 20000 项、保存 64 项明细，完整返回数组的 JSON 文本 UTF-8 SHA-256 保存为 `typeListSha256`，包含截断外变化。有效空数组为 `ok + []`，旧系统为 `unsupported + null`，异常为 `denied/error + null` 及异常类；不把未查询当作模式不支持 HDR。原模式 ID、分辨率、刷新率和屏幕整体 `hdr` 均保留，旧 JSON 不补写新字段，既有工作台支持模式表可直接查看、分页和比较新增字段。只读元数据，不切换显示模式、不播放或捕获画面；整体 HDR 列表不代表每种模式均支持相同类型，模式能力也不保证当前播放链路或许可证可用。

- TLS 展示补充（2026-10-26）：`security/tls-parameters` 的17个已知摘要字段以9行概览展示提供者、上下文、状态和四组列表数量/截断状态，完整原字段默认折叠，协议与密码套件原文仍在各组。完整哈希或未知元数据变化仍标记对应概览行差异，缺项、null、空字符串与未知状态保留区别；结构不完整时沿用原字段视图。仅调整浏览层，不改采集、比较规则、JSON原值或导出，不新增外部指纹结论。

- [SSLContext](https://developer.android.com/reference/javax/net/ssl/SSLContext) 的 `getDefault`、`getSupportedSSLParameters` 和 `getDefaultSSLParameters`，以及 [SSLParameters](https://developer.android.com/reference/javax/net/ssl/SSLParameters) 的协议/密码套件查询（2026-10-26 核对 SDK37，均自 API9 可用）：新增 `security/tls-parameters`，记录当前进程默认上下文的协议名、提供者名，以及支持/默认启用的协议和密码套件四组列表。对照 [OpenJDK jdk-25-ga 的 SSLContext](https://github.com/openjdk/jdk/blob/jdk-25-ga/src/java.base/share/classes/javax/net/ssl/SSLContext.java) 和 [SSLContextSpi](https://github.com/openjdk/jdk/blob/jdk-25-ga/src/java.base/share/classes/javax/net/ssl/SSLContextSpi.java) 的参数语义；[Conscrypt 固定实现](https://github.com/google/conscrypt/blob/48ee08228358c2289f422dd80b333b5ff33a7267/common/src/main/java/org/conscrypt/OpenSSLContextImpl.java) 提供默认上下文与协议配置的实现参考，不假定设备运行该上游版本。每组明细最多256项，保存完整原序 JSON 数组 UTF-8 SHA-256、数量与截断状态，保留顺序、重复、空字符串和null；缺失列表或输入超过4096项/单名称超过1024字符由ItemSink明确记录失败。查询可能触发默认上下文的惰性初始化，不连接远端、不握手、不设置默认上下文或修改提供者。只代表当前 App 的默认 JSSE 环境，不等同 WebView、其它 App、自定义客户端或真实 ClientHello/JA3/JA4，也不是TLS连接安全性或设备真实性结论；旧 providers 条目与旧JSON保留。

- [Android SELinux](https://source.android.com/docs/security/features/selinux)：说明 Android 运行时的 enforcing/permissive 策略状态与进程安全上下文。本工程新增 `security/selinux-summary`，只保存 enforcing 状态、上下文长度和 SHA-256，原始安全文件继续保留。

## 官方 Android 设备标识资料

- [Build](https://developer.android.com/reference/android/os/Build)：公开硬件、产品、指纹、ABI 等构建字段。
- [Build.VERSION](https://developer.android.com/reference/android/os/Build.VERSION)：公开 API level、版本、代号、增量版本、安全补丁、首发 API 和 API 31+ 媒体性能等级。本工程新增 `build/os-summary`，同时保留 `build/Build.VERSION/*` 原始字段，低版本字段保持 `null`。
- [PackageManager.getInstalledModules](https://developer.android.com/reference/android/content/pm/PackageManager#getInstalledModules(int)) 与 [ModuleInfo](https://developer.android.com/reference/android/content/pm/ModuleInfo)：API 29+ 公开 Mainline 模块名称、包名和隐藏标记。本工程新增 `build/module-summary` 与有界 `build/modules`，用全量集合 SHA-256 保留差异线索，不读取私有模块文件或未公开版本字段。
- [Build.SUPPORTED_ABIS](https://developer.android.com/reference/android/os/Build#SUPPORTED_ABIS) 与 [Process.is64Bit](https://developer.android.com/reference/android/os/Process#is64Bit())：公开应用可见的 ABI 顺序、32/64 位 ABI 集合和当前进程运行时位数。本工程新增 `build/abi-summary`，只保留架构族计数、主 ABI 和位数摘要，原始 `Build` 字段继续兼容保留。
- [Build](https://developer.android.com/reference/android/os/Build) 的硬件与 SoC 字段：公开制造商、品牌、型号、设备、产品、硬件、主板、构建指纹，以及 API 31+ 的 `SOC_MANUFACTURER`/`SOC_MODEL`。本工程新增 `build/hardware-summary`，构建指纹只保存长度和 SHA-256，避免在摘要中重复展开原始指纹；完整公开字段仍保留在 `build/Build/*`。
- [Settings.Secure.ANDROID_ID](https://developer.android.com/reference/android/provider/Settings.Secure#ANDROID_ID)：系统设置中的应用可见标识，生命周期和作用域受 Android 版本、用户和签名影响。本工程新增 `environment/android-id-summary`，只保存作用域、存在性、长度和 SHA-256；原始值/状态条目继续保留，不宣称它是永久硬件 ID。
- [Play Integrity verdicts](https://developer.android.com/google/play/integrity/verdicts)：官方完整性服务的 verdict 维度；本工程当前保持离线采集，未接入远程 Play Integrity 请求，因此相关结论保持 `skipped/unknown`。
- [MediaDrm](https://developer.android.com/reference/android/media/MediaDrm)：公开 DRM 厂商、版本、算法与 Widevine 支持。本工程的 `hardware/drm/widevine` 只保留 `deviceUniqueId` 的 SHA-256 与长度，原始唯一值永不写入指纹。
- Widevine 安全级别语义修正（2026-10-26）：[固定 AOSP 实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/MediaDrm.java#L2183-L2203) 的 API 28+ `getMaxSecurityLevel()` 始终返回请求最大安全级别用的占位常量 `6`，不是设备实测级别。历史 `maxSecurityLevel` 原值保留，新增 `maxSecurityLevelKind: "request-sentinel"`，工作台对新旧 JSON 都明确标注“最大级别请求常量”。独立新增 `securityLevelProperty`，复用原 Widevine 实例调用 API 18+ `getPropertyString("securityLevel")`，保留插件返回原文（包括空字符串）；[Google ExoPlayer r2.18.7 公开实现](https://github.com/google/ExoPlayer/blob/r2.18.7/library/core/src/main/java/com/google/android/exoplayer2/drm/FrameworkMediaDrm.java#L344-L347) 也读取该属性。插件不支持查询或抛异常时只将该对象记录为 `denied/error + null` 与异常类，不猜 L1/L3、不丢弃原有元数据；Widevine 不支持时沿用原有分支。只读属性，不打开 DRM 会话、不修改属性、不请求 provisioning 或许可证；该值不是会话级别认证、设备完整性结论或播放授权证明。旧 JSON 不补写新字段，未知值及缺项差异继续保留。
- [MediaDrm.getSupportedCryptoSchemes](https://developer.android.com/reference/android/media/MediaDrm#getSupportedCryptoSchemes()) 自 API 30 枚举平台支持的 DRM 方案 UUID；[固定 AOSP 实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/MediaDrm.java) 说明这些 UUID 可用于 `isCryptoSchemeSupported(UUID)` 和创建 MediaDrm。本工程新增 `hardware/drm-schemes`，只调用静态枚举接口，不创建插件实例、不打开会话、不发起 provisioning/授权请求。按 UUID 的标准小写字符串排序，保留重复项和未知 UUID，最多保存 32 项明细；完整排序 JSON 字符串数组的 UTF-8 SHA-256 记录在 `schemeListSha256`，包含截断外变化。空集合有效，缺失列表或 null UUID 不冒充空集合；API 低于 30 保留 `unsupported`，原 Widevine 条目和旧 JSON 不变。列表只说明 DRM 插件能力，不证明特定 MIME/安全级别的播放能力、许可证可用性或设备真实性，也不是永久硬件 ID。
- [UsbManager](https://developer.android.com/reference/android/hardware/usb/UsbManager) 与 [UsbDevice](https://developer.android.com/reference/android/hardware/usb/UsbDevice)：公开当前 App 可见的 USB 设备描述符和接口结构。本工程新增 `hardware/usb-summary` 与 `hardware/usb`；摘要限制 256 个设备、128 个 ID，记录厂商/产品 ID、类协议、接口/端点数量和权限查询状态，不复制设备路径、不申请设备权限、不读取序列号。
- [PackageManager.getSystemAvailableFeatures](https://developer.android.com/reference/android/content/pm/PackageManager#getSystemAvailableFeatures()) 与 [FeatureInfo](https://developer.android.com/reference/android/content/pm/FeatureInfo)：公开系统声明的硬件/软件特性、版本、标志和 OpenGL ES 要求版本。本工程新增 `hardware/features-summary`，同时保留 `hardware/features` 原始清单。
- [MediaCodecList](https://developer.android.com/reference/android/media/MediaCodecList) 与 [MediaCodecInfo](https://developer.android.com/reference/android/media/MediaCodecInfo)：公开媒体编解码器、支持的 MIME 类型和编码/解码方向，Android 29+ 还公开硬件加速、软件实现及厂商标记。本工程新增 `hardware/codecs-summary`，同时保留 `hardware/codecs` 原始能力。
- [CodecCapabilities.isFeatureSupported](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities#isFeatureSupported(java.lang.String))、[isFeatureRequired](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities#isFeatureRequired(java.lang.String)) 与[固定 AOSP 实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/media/java/android/media/MediaCodecInfo.java)（2026-10-26 已核对源码及 SDK）：前者区分可用特性，后者表示必须使用、始终开启的特性。`hardware/codecs` 的每项 MIME 能力新增 `featureFlags`，固定查询 `adaptive-playback`、`secure-playback`、`tunneled-playback`、`low-latency`，逐项保留 `status/supported/required` 原值；低延迟自 API 30 公开，旧系统保持 `unsupported + null`，不伪造 `false`。单项异常保留 `denied/error + null` 及错误类型，不丢失原有颜色格式、profile 和实例上限。只读取能力元数据，不创建、配置或启动编解码器；安全播放标志不证明 Widevine 安全级别、许可证可用性或实际播放成功。旧 JSON 不补写缺失标志，概览仍将深层特性变化计为差异，完整字段可展开。
- `hardware/codecs` 的工作台概览按原始数组序号逐项比较，每页 20 项，展示名称/规范名称、编码或解码方向、MIME 与硬件/软件/厂商能力。别名和重复条目不合并，API 29 以下缺少的能力字段不从名称推断；深层 profile、未知字段与单侧字段仍决定整行差异，完整字段默认折叠并可展开。旧 JSON 缺少必要字段或数组混合格式时回退原字段表，采集、比较规则、原值及导出不变。
- EGL、OpenGL ES 与 Vulkan 的公开运行时查询：本工程新增 `hardware/graphics-summary`，整理 EGL/GL 初始化、厂商、渲染器、版本、扩展长度与数量，以及最多 256 个 Vulkan 扩展名；完整 `hardware/graphics` 原始能力继续保留，避免把长扩展字符串重复展开到摘要。
- [CameraManager](https://developer.android.com/reference/android/hardware/camera2/CameraManager) 与 [CameraCharacteristics](https://developer.android.com/reference/android/hardware/camera2/CameraCharacteristics)：公开摄像头 ID、镜头朝向、硬件级别、传感器方向、闪光灯和逻辑多摄像头能力。本工程新增 `hardware/camera-summary`，同时保留 `hardware/camera/*` 原始特性，不读取图像帧。
- [CameraManager.getConcurrentCameraIds](https://developer.android.com/reference/android/hardware/camera2/CameraManager#getConcurrentCameraIds()) 与[固定 AOSP 源码](https://github.com/aosp-mirror/platform_frameworks_base/blob/1cdfff555f4a21f71ccc978290e2e212e2f8b168/core/java/android/hardware/camera2/CameraManager.java)（2026-10-26 已核对 SDK，API 30+）：返回当前连接摄像头中可由同一客户端并发配置会话的 ID 组合集合；空集合表示当前没有此类组合，不保证跨 App 并发，也不说明设备当前空闲。新增 `hardware/camera-concurrency`，只查询元数据，不打开摄像头、不创建会话、不读取图像、不调用需要 CAMERA 权限的会话配置验证。每组 ID 按字符串自然顺序排序，再按该 JSON 数组文本排序外层组合；完整 JSON 数组的 UTF-8 SHA-256 保存为 `combinationSetSha256`。最多展示 32 组、每组 16 个 ID，保留原始 ID 和成员关系，截断外变化仍进入哈希。有效空集合保留 `0 + []`，服务缺失保留 `unavailable + null`，API 30 以下为 `unsupported`，异常由原采集状态记录；不将未知/缺失数据猜为不支持，不把组合能力当作硬件永久标识或真实性结论。原摄像头摘要、特性与旧 JSON 不变。
- [Rational 官方 API](https://developer.android.com/reference/android/util/Rational) 与 [AOSP 实现](https://github.com/aosp-mirror/platform_frameworks_base/blob/main/core/java/android/util/Rational.java)（2026-10-26 已核对源码与本机 SDK）：该类型继承 Number，但有限值的 toString 为分数文本，特殊值为 NaN/Infinity，均不能直接作为 JSON 数字。本工程在公共 Json.value 中编码为 `{$type:"android.util.Rational",value:"1/6",numerator:1,denominator:6}`，覆盖单值、数组和集合，保留精确值及特殊值；避免摄像头元数据破坏整组硬件检查点。旧 JSON 与其它数值编码不变。

- [CodecCapabilities.getVideoCapabilities](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities#getVideoCapabilities())和[VideoCapabilities](https://developer.android.com/reference/android/media/MediaCodecInfo.VideoCapabilities)公开视频码率、帧率、宽高范围和宽高对齐要求。本轮以本机Android SDK35公开源码及SDK37.0的api-versions.xml核对：相关六项getter和视频能力类自API21可用，本工程minSdk24无需新版本门槛；远程源码下载超时，未声称核对本轮网络上的源码版本。
- `hardware/codecs[*].capabilities[*].videoCapabilities`新增固定对象：`bitrateBitsPerSecond`、`frameRatesPerSecond`、`widthPixels`、`heightPixels`各保存整数`lower/upper`，另有`widthAlignmentPixels`和`heightAlignmentPixels`。只读取当前App可见的公开能力，不创建编解码器、不扫描宽高组合、不播放媒体；范围是API返回限制，帧率不是实时性能指标，宽高/帧率上限不可任意组合成可播放结论，32位运行时也可能影响分辨率范围。

## 当前 App 可见的已安装 APEX 包

- API29+通过[PackageManager.getInstalledPackages](https://developer.android.com/reference/android/content/pm/PackageManager#getInstalledPackages(int))传入`MATCH_APEX`，仅保留`PackageInfo.isApex=true`的项，新增独立条目`build/apex-packages`。依据上述固定AOSP公开契约，仅表示当前已安装、已激活且对本App可见的包，不包含待重启激活的staged文件，也不声称是设备完整库存。
- 保留实际`packageName`、可空/可空字符串`versionName`及精确int64 `versionCode`；不将ModuleInfo配置包名强行映射到实际APEX，不替代原`build/modules`和`build/module-summary`。API29以下为unsupported，权限异常为denied，其它失败为error；缺失列表/null元素为错误，成功的空清单与查询失败分开。
- 输入最多20000项，筛选后按每项JSON序列化文本排序，保留重复；完整数组的UTF-8 JSON文本计算`packageSetSha256`，明细最多256项，返回总数、明细数、上限和截断标志，超限status为partial。哈希覆盖截断外的版本变化，版本不转JavaScript浮点数。旧JSON缺此条目仍可导入、对比，已有通用字段分页用于展示；任何单包或集合差异均不独立证明Root、系统真实性或补丁安全性。
- 真机验证（Pixel6/Android15，2026-10-26）：普通App公开枚举与独立Release采集均返回40个APEX包；`com.android.art`和`com.android.conscrypt`的版本号均为`352090000`，`com.android.i18n`为`1`，三者versionName均为null。原41项Mainline清单及其摘要与上一报告完全相同；这些观察仅对应当前设备状态。
- 展示：`packages`组默认按原始序号合并为包概览，每页20个包，直接比较包名、精确版本号和版本名，保留重复包名。未知字段参与整行差异，完整字段折叠后仍可展开并按50字段分页；空数组、旧结构缺少包名/版本号或复杂身份字段回退原字段表。null、空字符串和单侧缺项分别显示；窄屏可横向滚动到两侧版本及状态，原报告与比较规则不改。

## 系统字体公开元数据

- [SystemFonts.getAvailableFonts](https://developer.android.com/reference/android/graphics/fonts/SystemFonts#getAvailableFonts())、[Font](https://developer.android.com/reference/android/graphics/fonts/Font) 和 [AOSP SystemFonts](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/graphics/java/android/graphics/fonts/SystemFonts.java)（2026-10-26 已核对源码与 SDK）：API 29 起提供当前进程可见的系统字体集合。新增 `environment/system-fonts`，记录字体数量、文件来源数量、斜体/配置变体轴数量，以及文件 basename、TTC 索引、字重、倾斜、语言标签和排序后的变体设置；最多保存 128 项明细，并对完整元数据多重集合计算 SHA-256，保留无文件字体的 null。规范化记录为上述六字段的 JSON 数组，按字符串排序、每条追加 LF，再以 UTF-8 哈希；相同元数据不去重，避免无序 Set 导致差异。仅使用公开元数据 API，不调用 `getBuffer` 或读取字体正文，不导出完整路径、不改变字体配置；相同 basename 不证明来源相同，元数据哈希不等同字体文件哈希，不证明字形或实际渲染一致，也不是永久设备 ID。API 29 以下明确 unsupported，原始语言/字体缩放条目与旧 JSON 不变。

## GitHub 上的公开 SDK/实现

- [scottyab/rootbeer](https://github.com/scottyab/rootbeer)：README 列出 root 管理应用、危险应用、root cloaking、test-keys、危险属性、BusyBox、`su` 等检查，并明确说明这些规则有漏报和绕过限制。本工程只复用可观察证据（构建标记、属性、路径），不扫描或上传第三方应用清单作为结论。
- [RootBeer `Const.java` 固定版本](https://github.com/scottyab/rootbeer/blob/cc996259929da1e24bd0a7d017c818fd91910d17/rootbeerlib/src/main/java/com/scottyab/rootbeer/Const.java)（2026-10-26 经 GitHub API 核对）：`suPaths` 有 15 个固定目录，`getPaths()` 另外合并环境 PATH。本工程新增 `security/root-path-summary`，只检查固定目录中的 `su`/`busybox`，以及已有 `/vendor/bin/su` 与 `/data/adb`，共 32 项；不读取动态 PATH、不执行二进制、不跟随父目录符号链接，保留 errno，并区分存在、缺失、受限、未解析和其它错误。BusyBox 存在不构成 Root 结论，旧逐路径证据保持不变。
- 同一版本的 `pathsThatShouldNotBeWritable` 列出 7 个系统路径。本工程新增 `security/root-mount-summary`，通过公开 [Os.statvfs](https://developer.android.com/reference/android/system/Os#statvfs(java.lang.String)) 与 [StructStatVfs.f_flag](https://developer.android.com/reference/android/system/StructStatVfs#f_flag) 查询当前 App 挂载命名空间下的只读、nosuid、nodev、noexec 标志及原始 flags；由内核跟随符号链接并解析实际路径，逐项记录 errno 和未知值，不进行写入或 remount。`readOnly=false` 仅表示未设置只读挂载标志，不证明 App 具有写权限，也不生成 Root 判定。旧挂载拓扑摘要和原始挂载表保持不变。
- [talsec/Free-RASP-Community](https://github.com/talsec/Free-RASP-Community)：公开项目说明其检测范围包含 root/Magisk、Frida、模拟器、VPN、篡改和设备识别。仓库描述是能力分类证据，不能推导其私有实现字段；本工程将 VPN/模拟器/完整性拆成可复核条目。
- [fingerprintjs/fingerprintjs-pro-android](https://github.com/fingerprintjs/fingerprintjs-pro-android)：官方 Android SDK 仓库公开说明提供 Device Intelligence 与 Smart Signals。其具体信号由服务端返回，未在本工程复制未公开字段，后续仅作为供应商能力对照。
- `virtualization/risk-summary` 汇总 RootBeer/Talsec 类公开检查的路径存在性、构建字符串标记和 `test-keys` 线索；逐路径 JNI 结果仍保留，摘要只标记 `evidenceOnly`，不形成自动风控结论。
